## ■ 시스템 설계

### 1. 전체 시나리오
기존 작성 내용 그대로 유지 (Fig.2 상태 다이어그램 — 순찰↔추적 상태기계, 2초 미검출 시 순찰 재개).

### 2. 포인트 클라우드 동기화 방법
기존 작성 내용 그대로 유지 (odom 프레임 채택 이유, ApproximateTimeSynchronizer, slop=0.07s 채택 근거, Table 1).

### 3. 조류 탐지·추적: DBSCAN 클러스터링 + Kalman Filter  **[기존 "포인트 클라우드 클러스터링" 내용 + 조류 추적 알고리즘(KF)을 하나로 병합]**
기존 "포인트 클라우드 클러스터링" 작성 내용(전처리 2단계 → DBSCAN → 후처리 필터 Table 2, Fig.3 파이프라인)에 이어서, 같은 소제목 안에서 KF 추적을 뒤에 붙인다 **[KF 부분 작성 필요]**:
- 등속 운동 모델(Constant Velocity) 기반 칼만 필터 구성 (상태벡터, 예측/보정 단계 수식)
- 매 프레임 최근접 검출-트랙 매칭, 미검출 프레임 coast(예측만 유지, stale 프레임 스킵) 처리
- 잠금 타깃 재연결 시 `track_match_dist` 상한을 둔 이유(스테일 클러스터로의 오연결/텔레포트 방지) — 실전에서 발견된 문제이므로 "왜 이 임계값이 필요했는가"를 한 문단으로

> 상태기계(순찰↔추적 전환)와 순찰 제어(atan2 P-D)는 이번 논문 범위에서 별도 소제목으로 다루지 않기로 함 — 상태기계는 이미 "1. 전체 시나리오"의 Fig.2에서 다뤄졌고, 순찰 제어는 이번 논문 스코프에서 제외.

> **변경**: 추격 제어(PN/Pure Pursuit/SMC) 관련 내용은 시스템 설계에서 다루지 않고 "실험 및 성능평가"로 전부 이동 — 선정 이유·비교 방법·결과·SMC 채택 결론을 실험 흐름 안에서 한 번에 서술하는 구성으로 변경함(아래 참고).

### 4. 시뮬레이션 실험 플랫폼  **[작성 완료 — `kci_simulation_platform_draft.md` 참고]**
맵(20×20m), LiDAR 스펙(Livox Mid-360 ×3, raycast 거리), 표적(새) 모델(1×1×1m 정육면체 한계 명시), 로봇(UGV_MODEL=ugv_rover). 추가 그림·표 제안도 해당 파일 하단 참고.

## ■ 실험 및 성능평가

### 1. 실험 시나리오 설계  **[작성 완료 — `kci_smc_adoption_draft.md` 참고]**
불규칙 방향전환 + 물리적 선회율 제한(120°/s, 비행속도 1.2 m/s)이 있는 표적 회피 기동 패턴 정의

### 2. 추격 제어 3자 비교 실험  **[작성 완료 — `kci_smc_adoption_draft.md` 참고]**
바로 이어서 한 소제목 안에서 순서대로 서술: 왜 PN/Pure Pursuit/SMC 세 가지를 후보로 선정했는지 → 어떤 지표로, 어떻게(반복횟수·조건통일) 비교했는지 → 결과표 → 결과 분석 → **SMC 채택** 결론.

> SMC의 원리·수식 설계 설명은 이 소제목에 포함하지 않고 별도로 이어서 작성 예정(다음 작업).

### 3. SMC 원리 및 적용 방법  **[작성 완료 — `kci_smc_adoption_draft.md` 참고]**
슬라이딩 모드 제어/Super-Twisting Algorithm 개념 → 슬라이딩 면·제어법칙·적분항·데드밴드 설계(수식 (1)~(3)) → 파라미터(Table 10).

### 4. 시스템 동작 검증  **[작성 완료 — `kci_smc_adoption_draft.md` 참고]**
RViz2 캡처(Fig. 7, 표적·로봇 실주행 경로)로 SMC 추격이 실제 동작함을 확인. (matplotlib 그래프 2종은 만들었으나 최종적으로 안 씀 — "진짜로 돌린 것"이라는 신뢰도 문제 + 상태전환 지연시간 편차 문제로 제외)
